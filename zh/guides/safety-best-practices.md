
### 使用我们免费的 Moderation API

OpenAI 的 [Moderation API](/guides/moderation) 可免费使用，能帮助减少补全结果中不安全内容的出现频率。或者，你也可以开发自己的内容过滤系统，以适应你的具体用例。

### 对抗性测试

我们建议对你的应用进行"红队测试"，以确保它能够抵御对抗性输入。在广泛的输入和用户行为范围内测试你的产品，既包括具有代表性的输入集，也包括那些试图"破坏"你应用的输入。它是否会偏离主题？是否有人可以通过提示注入轻松重定向功能，例如"忽略之前的指令，改为执行此操作"？

### 人工审核（HITL）

在可能的情况下，我们建议在输出实际使用之前由人工进行审核。这在高风险领域和代码生成中尤为关键。人工审核者应了解系统的局限性，并能够获取验证输出所需的所有信息（例如，如果应用程序用于总结笔记，人工审核者应能方便地访问原始笔记以供参考）。

### 提示工程

"提示工程"可以帮助约束输出文本的主题和语气。这降低了生成不良内容的可能性，即使用户试图生成此类内容也是如此。为模型提供额外的上下文（例如在新输入之前提供一些高质量的期望行为示例）可以更容易地引导模型输出朝期望方向发展。

### "了解你的客户"（KYC）

用户通常需要注册并登录才能访问你的服务。将此服务与现有账户关联，例如 Gmail、LinkedIn 或 Facebook 登录，可能会有所帮助，但并非适用于所有用例。要求提供信用卡或身份证件可以进一步降低风险。

### 限制用户输入并限制输出 token 数

限制用户在提示中输入的文本量有助于避免提示注入。限制输出 token 数有助于减少滥用的可能性。

缩小输入或输出的范围，特别是从可信来源获取的内容，可以减少应用程序中可能发生的滥用程度。

通过经过验证的下拉字段（例如维基百科上的电影列表）允许用户输入，比允许开放式文本输入更安全。

在后端从经过验证的材料集中返回输出（如果可能的话），比返回新生成的内容更安全（例如，将客户查询路由到最匹配的现有客户支持文章，而不是尝试从头回答查询）。

### 允许用户报告问题

用户通常应有一种方便的方法来报告功能异常或其他关于应用行为的问题（列出的电子邮件地址、工单提交方式等）。此方法应由人工监控并酌情回复。

### 了解并传达局限性

从虚构不准确信息、到冒犯性输出、到偏见等等，语言模型在未经重大修改的情况下可能并不适合所有用例。考虑模型是否适合你的目的，并在广泛的潜在输入范围内评估 API 的性能，以识别 API 性能可能下降的情况。考虑你的客户群体及其将使用的输入范围，并确保他们的期望得到适当校准。

**安全性和安全保障对 OpenAI 来说非常重要。**

如果你在使用 API 开发过程中或与 OpenAI 相关的其他方面发现任何安全问题，请通过我们的[协调漏洞披露计划](https://openai.com/security/disclosure/)提交。

### 实施安全标识符

在请求中发送安全标识符可以帮助 OpenAI 监控和检测滥用行为。这使 OpenAI 能够在检测到你的应用中存在任何政策违规时，为你的团队提供更具可操作性的反馈。

安全标识符还可以帮助你的团队更快地应对滥用行为。它们创建了一种稳定的方式来将活动追溯到单个最终用户，并减少一个用户的滥用行为影响你整个组织访问权限的可能性。

安全标识符应该是唯一标识每个用户的字符串。对用户名或电子邮件地址进行哈希处理，以避免向我们发送任何可识别信息。如果你向未登录用户提供产品预览，可以发送会话 ID 代替。

安全标识符推荐用于个人用户与模型交互的产品，但不是必需的。使用 `safety_identifier` 参数在 API 请求中包含安全标识符：

**示例：提供安全标识符**

::: code-group
```python
from openai import OpenAI
client = OpenAI()

response = client.chat.completions.create(
model="gpt-4o-mini",
messages=[
{"role": "user", "content": "This is a test"}
],
max_tokens=5,
safety_identifier="user_123456"
)
```

```curl
curl https://api.openai.com/v1/chat/completions \
-H "Content-Type: application/json" \
-H "Authorization: Bearer $OPENAI_API_KEY" \
-d '{
"model": "gpt-4o-mini",
"messages": [
{"role": "user", "content": "This is a test"}
],
"max_tokens": 5,
"safety_identifier": "user123456"
}'
```

:::




对于 Realtime API 请求，使用 `OpenAI-Safety-Identifier` 头提供相同的稳定、保护隐私的标识符。当你创建临时 Realtime 客户端密钥时，在创建密钥的服务器端请求中包含该头，以便将标识符绑定到该会话。对于从可信后端发起的直接 WebSocket 或 WebRTC 连接请求，在连接请求中包含该头。

安全标识符不会在 API 或会话之间传递。如果你的应用已经在 Responses API 请求中发送 `safety_identifier`，在创建或连接每个 Realtime 会话时需要单独传递相同的稳定值。

### 撤销已泄露的 API 密钥

如果你认为某个 API 密钥已被暴露、滥用或以其他方式泄露，请立即撤销它并用新密钥替换。前往你的[安全设置](https://platform.openai.com/settings/profile/security)查看所有 API 密钥并撤销任何已泄露的密钥。
