# Safety in building agents

> 当你使用 [Agent Builder](/guides/agent-builder) 构建和部署智能体时，了解相关风险非常重要。

当你使用 [Agent Builder](/guides/agent-builder) 构建和部署智能体时，了解相关风险非常重要。了解风险类型以及在构建多智能体工作流时如何缓解这些风险。

## 风险类型

某些智能体工作流模式更容易受到风险影响。在聊天工作流中，两个重要的考虑因素是保护用户输入和谨慎使用 MCP 工具调用。

### 提示注入

**提示注入**是一种常见且危险的攻击类型。当不受信任的文本或数据进入 AI 系统时，就会发生提示注入，其中的恶意内容试图覆盖对 AI 的指令。提示注入的最终目标各不相同，但可能包括通过下游工具调用窃取私有数据、执行不当操作，或以非预期方式改变模型行为。例如，一个提示可能欺骗数据查询智能体发送原始客户记录，而不是预期的摘要。请参阅 [Codex 互联网访问文档](https://developers.openai.com/codex/cloud/internet-access/) 中的上下文示例。

### 私有数据泄露

**私有数据泄露**，即智能体意外共享私有数据，也是需要防范的风险。模型可能在没有攻击者的情况下，以非预期的方式泄露私有数据。例如，模型可能向 MCP 发送比用户预期或意图更多的数据。虽然护栏提供了更好的控制来限制上下文中包含的信息，但你无法完全控制模型选择与连接的 MCP 共享什么内容。

使用以下指南来减少攻击面并缓解这些风险。但是，_即使采取了这些缓解措施_，智能体也不会完美，仍然可能犯错或被欺骗；因此，了解这些风险并谨慎对待你赋予智能体的访问权限以及如何应用智能体非常重要。

## 不要在开发者消息中使用不受信任的变量

由于开发者消息优先于用户和助手消息，将不受信任的输入直接注入开发者消息会给攻击者最高程度的控制权。通过用户消息传递不受信任的输入以限制其影响。这对于将用户输入传递给敏感工具或特权上下文的工作流尤为重要。

## 使用结构化输出来约束数据流

提示注入通常依赖于模型自由生成意外的文本或命令，这些内容会向下游传播。通过在节点之间定义结构化输出（例如枚举、固定模式、必需字段名），你可以消除攻击者可以利用来走私指令或数据的自由格式通道。

## 通过清晰的指导和示例引导智能体

由于幻觉、误解、模糊的用户输入等原因，智能体工作流可能会执行你不希望的操作。例如，智能体可能提供不应该提供的退款或删除不应该删除的信息。缓解此风险的最佳方法是通过良好的策略文档和清晰的示例来加强你的提示。预见非预期场景并提供示例，以便智能体知道在这些情况下该怎么做。

## 使用 GPT-5 或 GPT-5-mini

这些模型在遵循开发者指令方面更加严格，并且对越狱和间接提示注入表现出更强的鲁棒性。在智能体节点级别配置这些模型以获得更具弹性的默认姿态，特别是对于高风险工作流。

## 保持工具审批开启

使用 MCP 工具时，始终启用工具审批，以便最终用户可以审查和确认每个操作，包括读取和写入。在 Agent Builder 中，使用 [human approval](/guides/node-reference#human-approval) 节点。

## 对用户输入使用护栏

使用内置的[护栏](/guides/node-reference#guardrails)来清理传入的输入，以编辑个人身份信息（PII）并检测越狱尝试。虽然 Agent Builder 中的护栏节点本身并非万无一失，但它们是有效的第一道防线。

## 运行追踪评分器和评估

如果你了解模型在做什么，就能更好地发现和防止错误。使用[评估](/guides/evaluation-getting-started)来评估和改进性能。追踪评分为智能体追踪的特定部分提供分数和注释——例如决策、工具调用或推理步骤——以评估智能体在哪些方面表现良好或犯了错误。

## 组合使用多种技术

通过组合这些技术并加固关键步骤，你可以显著降低提示注入、恶意工具使用或意外智能体行为的风险。

设计工作流时确保不受信任的数据永远不会直接驱动智能体行为。仅从外部输入中提取特定的结构化字段（例如枚举或经过验证的 JSON），以限制注入风险在节点之间流动。使用护栏、工具确认和通过用户消息传递的变量来验证输入。

当智能体处理影响工具调用的任意文本时，风险会增加。结构化输出和隔离可以大大降低，_但不能完全消除_，这种风险。
